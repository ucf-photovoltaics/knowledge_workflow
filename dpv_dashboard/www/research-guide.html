Explore the research. Follow the evidence.

The dashboard connects saved literature findings to formal ontologies. Select an experiment and run above each dashboard page. An integrated run connects multiple domains; a domain run contains that domain's source papers and decisions.

Your first five minutes

  1. Open Visual Exploration. The default Gemma integrated ontology provides a starting overview.
  2. Search a concept or paper title. Search covers the selected research scope, including concepts outside the visible graph.
  3. Select a result and focus it in the graph. Click a node to inspect its meaning and connections; double-click to open its evidence trace.
  4. Click a relationship label to inspect its origin, quotes, conditions and papers. Some ontology edges have no recorded paper-level evidence.
  5. Use Quality review and Reports & figures before deciding what can be concluded or reused.

A worked research route

Search for degradation rate. If a matching concept is recorded, focus it and choose a one-hop neighborhood. Inspect one recorded relationship and its source paper. Check the quote's surrounding context and experimental conditions. Use cross-domain connections to inspect recorded mappings toward other domains. If no matching link is recorded, the dashboard should report that absence rather than invent a connection.

This is an exploration route, not a claim that every selected run contains this concept or a causal path to cost outcomes.

1. Literature selection

Input: a research library. Process: select distinct papers under saved inclusion, ranking and per-domain limits. Output: the corpus used in the run. Inspect the actual selected papers, exclusions and PDF availability. Citation ranking does not establish scientific reliability.

2. Parsing

Source papers are converted to text, sections and available figure records. Review coverage by paper before treating a missing claim as a scientific absence. The source PDF and parsed text may differ in coverage, especially for equations, tables and scanned content.

3. Evidence extraction

Concepts, statements and measurements are extracted from parsed passages. Inspect the subject, relationship, object, quote and conditions. “Quote located in parsed text” means textual matching; it does not establish that the passage supports the whole interpretation.

4. Terminology consolidation

Original terms are linked to shared names, called canonical concepts. Inspect original-to-shared lineage and paper context to assess merges. A reconstructed label association is different from a recorded model decision.

5. Ontology placement

Shared concepts are placed under ontology categories. Read the concept definition, proposed parent and placement rationale together. A category assignment is a modeling decision, not a scientific measurement.

6. Enrichment

Definitions and formal relationships may be added. Inspect whether a definition was imported, generated or supported by paper evidence, and read any review flags. An imported name alone does not establish that the imported meaning fits the local concept.

7. External vocabulary mappings

Mappings link local terms to external vocabularies. Compare both definitions. Equivalence, broader/narrower meaning and relatedness have different implications for reuse. Exported Turtle and JSON-LD are machine-readable ontology formats; evidence and reports provide context that the ontology file alone may not contain.

8. Domain integration

Integration records mappings and bridge concepts across domain ontologies. Inspect both source concepts and domain evidence. Upstream pages offer a contributing-domain selector while the integrated run stays selected globally. A chain of mappings or graph edges does not establish a causal explanation.

9. Reports and figures

Read the saved report alongside corpus coverage and quality assessments. Check axes, units, denominators, sampling and input versions. Structural counts are not measures of scientific correctness. Export provenance and citations with any filtered graph figure.

Terms used in the dashboard

Ontology
A formal vocabulary of classes and modeled relationships or constraints.
Canonical concept
The shared name used to consolidate original terms within this run.
Literature claim
A statement reported in a paper, with whatever source evidence and conditions were recorded.
Restriction
A formal constraint in the ontology; it is not necessarily an experimentally observed relationship.
Mapping
A recorded relationship between concepts in different vocabularies.
Provenance
The source records and transformations explaining where a result came from.
IRI
The full machine-readable identifier for a concept or relationship. Labels can be similar while IRIs remain distinct.
Not recorded
The saved outputs do not establish the value or decision. This does not mean zero, false, or passed.

Interpretation and reproducibility

The graph is a bounded view of saved outputs. Hidden or collapsed nodes are not missing from the ontology. Path searches explicitly choose relationship origins, direction and maximum depth; a failed search is conditional on these choices. Paper comparisons match DOI first, otherwise exact paper key and title, and compare labels only within shared papers. Label agreement is not semantic agreement or model-quality ranking.

Quality review distinguishes saved ontology-check reports from malformed records withheld from search and chat. A missing report means not recorded. Inspect the input fingerprint and assessment time before using an old report for a changed ontology. Scientific acceptance requires appropriate human review beyond structural or logical checks.

Browser-saved views retain only display choices. Exports identify the source scope and fingerprints. Access rules still apply when a source is opened. AI chat is optional and sends the question and selected evidence to the configured provider; ordinary evidence search needs no API key.
